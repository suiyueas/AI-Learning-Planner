🧠 设计理念

将传统「问答式AI」升级为「代理式AI（Agentic AI）」，模拟人类解决问题的思维方式：理解目标 → 分解任务 → 执行操作 → 观察结果 → 调整策略。通过 ReAct（Reasoning + Acting）模式实现「边思考边行动」的闭环。

🔄 ReAct 推理-行动-观察闭环

推理 (Think) → 行动 (Act) → 观察 (Observe) ↻
推理
当前状态？下一步？
行动
调用工具、查询数据、执行
观察
分析结果，迭代更新
终止条件：正常完成 · 最大迭代（30轮）· 重复检测（相似度＞90%）· 超时（30秒）

数据存储架构 · 完整数据模型

💡
设计决策： 本项目采用 MySQL + Elasticsearch 混合存储 架构。MySQL 负责核心业务数据的 ACID 事务与关系约束；Elasticsearch 承担向量检索、全文搜索与日志分析，满足海量数据下的高性能查询。Redis 作为缓存与任务队列，加速热点访问并解耦异步任务。
🗄️ MySQL 核心业务表（9 张） ACID 事务保障
存储用户、知识图谱、学习路径等核心业务实体，利用外键与事务保证数据完整性。
user — id, username, password_hash, email, created_at
user_profile — user_id, learning_style, level, active_hours, target_field
knowledge_node — id, name, description, difficulty, estimated_hours, prerequisites(JSON)
learning_path — id, user_id, name, version, status, created_at
learning_path_node — id, path_id, node_id, sequence_order, status, mastery
resource — id, title, type, url, node_id, avg_rating
chat_history — id, session_id, user_id, role, content, created_at
intervention — id, user_id, type, trigger, content, created_at 新增
achievement — id, user_id, badge, unlocked_at 新增
🔍 Elasticsearch 索引（8 个） 全文 · 向量 · 日志
承载 RAG 向量检索、全文搜索以及学习日志聚合分析，支撑智能问答与数据洞察。
users — 用户基础信息 + 画像（合并宽表）
knowledge_nodes — 知识图谱节点，含 1536 维 dense_vector
learning_paths — 用户学习路径，node_sequence 嵌套对象
learning_records — 学习记录，按时间分索引（如 records-2026.07）
resources — 学习资源，支持全文搜索
chat_histories — 对话历史，按 session_id 路由
interventions — 学习干预记录 新增
achievements — 学习成就与打卡 新增
⚡ Redis 缓存与队列 会话 · 热点 · 任务
内存级高速缓存，用于缓解 MySQL/ES 查询压力、管理用户会话与异步任务。
Session — 用户登录态与对话上下文
Hot Cache — 热点知识图谱、常用资源列表
Task Queue — 干预检测、报告生成等异步任务
Rate Limiter — 大模型 API 调用频控计数
🔄 事务与一致性保障 MySQL 强一致 · ES 最终一致
分层处理不同场景下的一致性需求，确保业务可靠性与查询性能的平衡。
MySQL 层： @Transactional 事务注解保证 ACID
ES 层： 乐观锁 _version + @EventListener 异步同步 + Spring Retry 重试
关键操作： 用户注册强制 refresh=true，保证立即可见
跨索引更新： 使用 update_by_query 批量处理

关键技术决策

1

MySQL 关系型存储（强一致性）

存储用户、知识图谱、学习路径等 9 张核心业务表，利用外键与事务注解 @Transactional 保证 ACID，适用于对数据一致性要求高的业务场景。

2

Elasticsearch 向量 + 全文检索（8 索引）

承担 RAG 向量检索、全文搜索与日志分析，利用 dense_vector 实现 kNN 语义检索，混合 BM25 与向量加权，支撑智能问答与数据洞察。按时间分索引（如 learning_records）便于数据滚动。

3

ReAct + 分层智能体架构

主控Agent + 7个子Agent，ReAct循环引擎内置推理-行动-观察闭环，配合终止工具、重复检测、最大迭代（30轮）等机制防治死循环。

4

最终一致性 + 版本控制（跨库）

MySQL 强事务保障主数据，ES 采用乐观锁 _version + @EventListener 异步同步 + Spring Retry 重试，关键操作强制 refresh=true，确保跨库数据的最终一致性。

5

多模型动态切换与降级

通过环境变量 MODEL_PROVIDER 在 Qwen、DeepSeek、MiMo、Ollama 间切换，若主模型不可用自动降级到备用模型，保证高可用。
